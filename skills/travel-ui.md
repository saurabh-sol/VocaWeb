# Travel UI

**Purpose:** Design UI patterns for booking/itinerary/travel products.

**When to use:** When building search, booking, or itinerary interfaces.

## Core Principles

- Search/filter (dates, destination, price, stops) should be persistently visible/editable while browsing results.
- Show total price inclusive of major fees upfront in search results, not just a low base price.
- Use maps as a first-class element for location-based browsing (hotels, activities), not an afterthought.
- Group itinerary items chronologically with clear day/time structure.
- Show real-time or near-real-time availability/status where relevant (seat count, sold out, price changes).

## Reference Sources

- Booking/travel UX pattern references — Land-book, Mobbin travel category

## Checklist

- [ ] Search/filters persistently editable
- [ ] Total price shown upfront including major fees
- [ ] Itinerary structured chronologically with clear day/time grouping

## Common Pitfalls

- Low 'teaser' prices that balloon at checkout
- Search filters hidden/reset when returning to results
- Itinerary items with no clear chronological structure
