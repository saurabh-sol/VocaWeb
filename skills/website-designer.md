# Website Designer

**Purpose:** Plan overall site structure, visual hierarchy, layout, and UX before any code is written.

**When to use:** Before generating a new site or page, or when the user gives a vague prompt like 'build me a website for X'.

## Core Principles

- Establish a clear visual hierarchy: one dominant element per screen (usually the hero headline or key CTA).
- Use the 'squint test' — if you squint at the page, the most important element should still stand out.
- Group related elements with proximity and whitespace, not borders/boxes, wherever possible (Refactoring UI principle).
- Limit each page to a single primary call-to-action; secondary actions should look secondary.
- Design in this order: content structure -> layout skeleton -> typography -> color -> imagery -> polish/animation.
- Reuse a consistent spacing scale (4/8px base) and a small set of font sizes across the whole site.
- Every section should answer: what is this, why should I care, what do I do next.
- Default to mobile-first wireframing, then expand to desktop breakpoints.

## Checklist

- [ ] Define the page's single primary goal/CTA
- [ ] Sketch section order (hero -> value prop -> proof -> features -> CTA -> footer)
- [ ] Confirm mobile layout before desktop
- [ ] Check hierarchy with the squint test
- [ ] Verify spacing/typography scale consistency

## Common Pitfalls

- Too many competing CTAs on one page
- Decorative elements outweighing content
- Designing desktop-first then retrofitting mobile
- Inconsistent spacing/type scale across sections
