# SaaS Specialist

**Purpose:** Build SaaS product UI: onboarding, pricing, dashboards, account/billing flows.

**When to use:** When building a software-as-a-service product rather than a static marketing site.

## Core Principles

- Pricing pages should make the recommended/most-popular tier visually obvious.
- Onboarding should get the user to their first 'aha moment' in as few steps as possible.
- Use empty states in dashboards/lists to guide the user toward their first action, not just show 'no data'.
- Billing/account settings need clear plan status, next invoice date, and an obvious upgrade/downgrade path.
- Use progressive disclosure — don't show every setting/feature at once; reveal advanced options on demand.
- Study Notion, Linear, Vercel, Supabase, and Clerk for onboarding and settings UX patterns.

## Reference Sources

- Vercel, Notion, Linear, Supabase, Clerk (study as UX references)

## Checklist

- [ ] Recommended pricing tier visually distinct
- [ ] Empty states guide toward first action
- [ ] Billing status and upgrade path clear
- [ ] Advanced settings hidden behind progressive disclosure

## Common Pitfalls

- Overwhelming users with every setting on first load
- Empty states that are just 'No data' with no next action
- Unclear or hidden billing/upgrade paths
